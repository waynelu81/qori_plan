# T-147 — report

## Outcome

A sign-up now runs `CreateGroupForNewUser` once instead of twice. Laravel's
event discovery was already registering the listener, and
`AppServiceProvider::boot()` registered it a second time by hand; that line is
gone. Nothing a person sees has changed, because the second run always
returned early. What has changed is that the next listener cannot quietly run
twice: `ListenerRegistrationTest` fails if any listener is registered twice
for one event, if a class in `app/Listeners` is registered anything but once
for the event its `handle()` takes, or if one `Registered` event asks
`GroupService` for more than one Group. `CLAUDE.md` states the rule, and
`docs/flows/auth.md` says how the listener is registered and gives the reason
for hanging it off the event that still holds.

## Departures

- `T-044`'s draft cited `AppServiceProvider::boot()` as `:41-49`; the deleted
  line moves it to `:38-44`, and the citation now says so. Listed in the task

## Found, not fixed

- `package.json` has no `name`, so `npm install` in a worktree rewrites
  `package-lock.json`'s root `name` to the worktree's directory
  (`nostalgic-curie-6d3ea1` here). `/do` tells every worktree run to
  `npm install`, so every one dirties the lockfile, and a worker who stages
  everything commits it; it was restored here before each commit. A
  `"name": "qori"` line in `package.json` ends it → decided: not a task; it is
  one line for the owner to add with the next change to the build files, and
  until then a worker restores the lockfile before committing
- 28 test methods in eight starter-kit files (`tests/Feature/Auth/RegistrationTest.php`
  and seven like it, under `tests/Feature/Auth` and `tests/Feature/Settings`)
  declare no return type, against `CLAUDE.md`'s "Explicit return types on
  every method, including tests". Pint's `laravel` preset does not require
  one, so the gate is green without them → decided: not a task; every one
  still runs, and the rule is a style rule that a pint setting could enforce
  the day a workflow task chooses to
- `ReachabilityTest::test_every_allow_list_entry_has_a_reason` performs no
  assertion while `Reachability::allowed()` is empty, so every gate run
  reports one risky test, and a reader who does not look assumes it is theirs
  → decided: not a task; an empty allow-list is the aim, the loop starts
  asserting the day an entry is added, and the risky count says exactly that
