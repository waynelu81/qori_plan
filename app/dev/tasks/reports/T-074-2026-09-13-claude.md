# T-074 — report

## Outcome

The code is the last thing a stranger is asked. The §9 box sits on the first
form beside the name and the email, travels with the pending step, and the
moment the code is right the page does the button's work: a free Series is
granted and opened, a paid one goes straight to Stripe's checkout with the
email filled in. A name, an email, a tick and a code, and nothing else. The
signed-in button got its consent box back, which it had lost. Coming back
from Stripe before the webhook has granted access now shows "Confirming your
payment", which asks the server again every three seconds and turns into the
Series on its own, instead of a 403. Cancelling at Stripe lands on the Series
with "Nothing was charged" on the page, instead of on a list of nothing.

## Departures

**`CheckoutPending` takes the Series id**, not the model, because the shared
page receives the id and has no model until access is found.

**`verify()` takes `AccessService` and `CheckoutService` by method
injection**, keeping the constructor to the one service the controller is
about, per the controller rule.

**A stranger opening the cancel URL gets no note.** Nothing of theirs was
started; the note is for the person who was at Stripe.

**The `slow` line is client-side**, measured from `startedAt`, so a page
reopened later says so at once rather than after another two minutes.

## Found, not fixed

- **Toasts flashed before a redirect the browser follows as a full page load
  never show.** That is every return from Stripe: `payouts.ready` and
  `payouts.pending` after onboarding (`T-064`), `payouts.connected` and
  `payouts.declined` after OAuth (`T-063`). The Integrations page renders the
  status anyway, so nothing is wrong on screen, but the sentences were
  written for nothing. Needs a task: dispatch the flash on the initial page as
  well, or render those as notices too.
- The checkout page is titled with the connected account's Stripe display
  name, which for the owner's sandbox account reads "Harbour Lane Studio". A
  Stripe dashboard setting, not Qori's; worth knowing before it surprises.
- The public page still offers the buy button for a Group that has
  disconnected Stripe; case 4 is what a buyer meets then. Still wants its own
  task, as `T-064` and this task's Notes say.
