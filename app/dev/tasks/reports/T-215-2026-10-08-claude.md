## Where the specification was wrong

| Section | Said | Actually |
| --- | --- | --- |
| Decisions | A fresh clone running the workflow's steps on this Mac proves them "before it is trusted" | It proved everything but one condition. A clone here has a migrated database to hand, and CI's build step does not: `.env` names `qori`, and the runner's Postgres has only `qori_testing`. Wayfinder types a bound model's key from the database's columns and falls back to docblocks when it cannot connect. So on CI the passkey route's id came out as `number`, and `vue-tsc` failed on `ManagePasskeys.vue` in the first GitHub run (37721828269, 8 October, 03:16 UTC), after Setup Node, the install and the build had all passed. Reproduced here with `DB_DATABASE` set to a database that does not exist (`number`) against a migrated one (`string`). The build step now migrates `qori_testing` before Wayfinder runs |
