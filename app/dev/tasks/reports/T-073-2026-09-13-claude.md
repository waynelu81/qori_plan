# T-073 — report

## Outcome

A stranger holding a Series link gets in without leaving the page. The public
Series page offers a name and an email; submitting them makes an account with
no password and no Group, or finds the account the address already has, and
sends a six-digit code whose subject is the code. The page then shows six
slots where they type it, with resend and start-over beside them. A right
code marks the address verified, fires `Verified`, signs them in and
regenerates the session, and they are back on the Series with the access
button showing. A wrong code, a spent code and a missing start are each
refused in their own words. The sign-in link stays for whoever has a
password. Seven screens and a change of app became one page and a
notification.

## Where the specification was wrong

| Section | Said                                                          | Actually                                                                                                                                                                                                   |
| ------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Code    | Fire `Registered` with `signup_intent=learn` merged in        | The framework answers `Registered` by mailing a verification link, so the person would get a link and a code for one address. Not fired. The only Qori listener skips a learner anyway, so nothing is lost |
| Routes  | `resend()` merges the pending email so the limiter keys on it | Middleware runs before the controller; the limiter keys on an empty email and the IP. Resend is three a minute per IP, and a code allows five attempts regardless                                          |

## Departures

**The code mail joined `qori:mail:check`**, sent through the service, and
the mail test's service map learned the pair; the command reads seven
messages back now and did so locally. The task's Files table had neither the
command nor `docs/tinker/mail.md`.

**Series URLs are template strings** in the page, as the Integrations page
does, rather than the generated route helpers, which exist only once the
routes have been generated.

**The step's user is re-read** on resend and verify, and a step whose user
has gone is forgotten and refused as `nothing_pending`, so a deleted account
cannot leave a session pointing at nothing.

## Found, not fixed

- **The signed-in "Get access" button has no consent box.** `Series.vue`
  declares `consented` and the comment says it gates both buttons, but the
  template has no checkbox and the form posts no `consent`, so the free path
  fails `GrantInSeriesRequest` with an error the page never shows. The paid
  path has no such rule and works. `T-074` moves consent onto the first form
  and must put the box back on the button for a signed-in person. → decided:
  fixed — the signed-in form carries the required terms box and the optional
  emails box on the free and paid paths alike (`T-178`, 22 September 2026),
  seen in the built-in browser on 23 September (triaged 23 September 2026)
- The pane's viewport was left at phone width by an earlier check and reset
  at the end; nothing to fix. → decided: nothing to fix, as the finding says
  (triaged 23 September 2026)
