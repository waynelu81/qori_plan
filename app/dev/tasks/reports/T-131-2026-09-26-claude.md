# T-131 — report

## Outcome

A Peer can reach an Episode's materials now. Each Episode row on
`/shared/{seriesId}` lists them under Preparation, Material and Homework, in
the creator's order, each with **Open** — a plain link in a new tab to
`shared.materials.open`, which passes the Series page's gate, checks release,
writes an `access_opens` row, marks the Episode opened and redirects: to the
pasted link, or to a signed link to Qori's own storage that lives as long as a
document link does. A row the creator listed "After the session" reads "Shown
after the session" with no link until Join's window has closed; its address
opened early lands back on that Episode's row with "That's shown after the
session. The rest of this Episode is below." A homework shows its brief and
"Due" in the reader's own zone with the Group's beside it, and a brief-only
homework shows its brief and due date and nothing to press. A pasted link says
it is a link the creator manages. No access is a 403, a file that never
arrived or an empty homework is Qori's 404, and the public page carries no
material at all.

## Departures

- **A material's due date is stored as its instant in UTC.** Eloquent's
  datetime cast writes a Carbon's own wall-clock digits, so a zoned time
  handed to `MaterialService::add()` or `update()` — by tinker or a job; the
  creator's requests convert first — landed hours out. Found while seeding the
  walk; `?->utc()` on both, and a test case.
- **The list mounts after the live card and before Mark as done**, so
  finishing stays the row's last line; the spec's "after the row's controls"
  read either way.
- **A live Episode with no start holds its "After the session" rows**: it has
  no session end for "after" to follow.
- **"A link the Creator manages" shows on a link row with an address only**,
  not on a brief-only homework, which links nowhere.
- **The creator's page no longer sends the Peer's lines**:
  `SeriesController::materialsCopy()` hands the panel every line of
  `materials.php`, which now included `peer.*` and `not_yet`; it leaves them
  out.
- **Docs this task made untrue, beyond the Files table**:
  `docs/flows/live-sessions.md`'s open log said nothing writes a `material`
  row; `docs/flows/storage.md`'s progress note said Open was the only way a
  Peer reaches material, and its provider table that the local disk cannot
  sign — it serves and signs its own, as the tinker run showed, and
  `CloudflareR2Storage::temporaryLink()`'s comment said the same and is
  corrected. `docs/flows/README.md`'s materials row names the Peer's side.
  `docs/tinker/accesses.md`'s Setup named the Series service and a Peer record
  in ways that no longer ran, its jsonb check queried `series.episodes`, which
  is its own table now, and its draft-guard block now says Free's Series cap
  refuses first.
- **Four cases beyond the 18** in `OpenMaterialTest`: an "After the
  session" row on a live Episode with no start (19); release read with no
  Group left current from a creator's request (20), the one case that fails
  if either `runFor()` goes; two opens writing two rows and marking the
  Episode once (21); and a due date given in another zone stored as its
  instant (22). Every negative assertion was made to fail once in a scratch
  copy, and each `runFor()` and `utc()` was removed in turn to see which case
  catches it.

## Found, not fixed

- The dev web server, started by `composer dev` on 18 September, still hands
  its child the `R2_BUCKET` it loaded then (`useqori-app-bucket`), while
  `.env` has named `useqori-app-bucket-test` since 23 September; so a page
  signs links for one bucket and the command line writes to the other. An
  environment matter, not code → decided: told to the owner on 26 September;
  restarting `composer dev` lines them up
- `materials_content_matches_provider` exempts every homework row from the
  provider rule, so the database would take a Dropbox homework or a
  Qori-hosted one with no asset; the service and the form refuse both, and
  that is the only road to `open()`'s unsupported arm (400) → decided: the
  exemption is `T-130`'s, on purpose, for a brief-only row, and `T-094`,
  `T-096` and `T-098` rewrite the CHECK when they add their providers
- The Peer's list marks every Qori-hosted row `isOpenable`, including one
  whose upload never arrived → decided: unreachable, since `add()` requires a
  stored asset; case 12's 404 is the backstop
