# T-003 — report

## Outcome

Sixteen product pages measured at 360px: **none scrolls sideways**. The palette
is a test now rather than an afternoon's arithmetic — `PaletteContrastTest`
parses `resources/css/app.css` and asserts every pair that matters in both
themes, so the next person to nudge a token finds out in the same run that
checks everything else.

The keyboard third could not be done here and was split into `T-022`. That is
the significant part of this report and it is below.

**Could not verify — the whole keyboard third.** The browser pane was hidden,
and `document.hidden === true` has three consequences:

- **Key events do not reach the document.** `Tab`, with focus explicitly placed
  in a text field first, left `document.activeElement` unchanged. Tab order and
  focus rings could not be observed at all.
- **CSS animations do not run in a hidden document**, so `animationend` never
  fires and Reka's exit transition never completes. Escape _does_ work — the
  archive dialog's `data-state` goes to `closed` — but the element stays
  mounted and focus is never restored, so "returns focus sensibly" is
  untestable rather than failing.
- `/u/security` answers 423 rather than 200, which is correct (it wants
  password confirmation) and is noted so the next reader does not chase it.

## Departures

**Two fixes, both under the ten-minute line the task set:**

1. `errors/layout.blade.php` had three dark values — `--ink`, `--muted`,
   `--gold` — that were hand-picked rather than converted, and had drifted from
   the tokens they were copied from. **The new test caught this on its first
   run.** The file already carried a comment saying the values were duplicated
   and must be kept in step; a comment is not a mechanism, and this one had
   already failed.
2. `DialogContent` forwarded its own `showCloseButton` prop into Reka, which
   does not know it, so `showclosebutton="true"` landed on the DOM of every
   dialog in the product. `reactiveOmit` drops it now. Upstream shadcn-vue has
   the same bug.

**The task was re-scoped and then resolved by splitting**, rather than blocked.
Two thirds were complete and independently valuable; blocking the whole thing
would have shelved a contrast test that will outlive every screen it was
written for.

## Found, not fixed

**`T-022` — the keyboard and focus pass**, blocked on an environment that
receives key events. Everything known about it is written down there, including
what was half-observed: Escape reaches Reka, and what happens after it is
unknown.

**A hidden browser pane has now silently changed what was observable three
times** in this project — `requestAnimationFrame` in `useDeepLinkedControl`,
which shipped broken twice; animation-gated unmounts here; and key delivery
here. It is not a product problem and there is no task for it, but the runbook
should say it, because the failure mode is always the same: the environment
does not error, it just quietly answers a different question.
