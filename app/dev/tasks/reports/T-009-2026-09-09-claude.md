# T-009 — report

## Outcome

`Series::STATUS_ARCHIVED` was declared in the schema migration and read by
nothing — a constant with no behaviour, which left a creator over their plan
cap exactly one exit: pay more. Archiving now takes a Series out of the cap and
off the public page while every Peer who has access keeps it, and the
confirmation says how many people that is before the click.

That last part is the whole design. A creator archiving to get under a cap has
to be able to trust that the people who paid keep what they paid for, and §5's
rule is that a plan cap removes capabilities and never removes the ability to
honour an obligation.

## Where the specification was wrong

| Section | Said                                                         | Actually                                                                                                                  |
| ------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Files   | "exclude from `scopeCounted()`"                              | No such scope exists. Implemented `isArchived()` / `scopeArchived()` / `scopeUnarchived()` as the Code section describes. |
| Copy    | `errors.series.cap_reached`                                  | Does not exist. The equivalent is `errors.series.limit_reached`.                                                          |
| Code    | "`Group::seriesUsed()` changes to count `unarchived()` only" | The cap is counted in **four** places, not one. See below.                                                                |

**The cap was counted four times.** Changing only the one the spec named
produced a half-working feature that still refused to create anything:

1. `Group::seriesUsed()` — named in the spec.
2. `SeriesService::guardSeriesLimit()` — ran its own query. Now delegates, so
   the cap has one definition instead of two that can disagree. They already
   did: `isOverSeriesCap()` released the lock while this still refused.
3. `SeriesController::index()` — counted the rows it was about to render,
   which include archived ones. **Found in a browser**: the page said "1 of 1
   used" immediately after archiving to get under the cap.
4. The at-limit copy in the New Series panel, still offering "delete".

A spec that says "change this counter" should list every place it is counted.

## Departures

Two tests beyond the nine specified. One asserts the page's `limits.used` prop
rather than the model, because the browser found a defect every model-level
test had passed through. One asserts on the service directly that archiving is
**not** behind `guardSeriesUnlocked` — archiving is the escape from that lock,
and a guard added there later would still let every route test pass by way of
the controller redirecting.

The acceptance line about deletion promises was ambiguous about which files it
meant, and I originally changed only one. It now names all three, and all three
are corrected — including `lang/en/errors.php`, whose own comment read "Not
'archive': there is no archive, and offering a way out that does not exist is
worse than naming the two that do."

## Found, not fixed

`SetCurrentGroup` replaces the `{group}` route parameter with the resolved
`Group` model, so the argument bound to `string $group` is not the slug a URL
needs — building a redirect from it throws `UrlGenerationException`. `store()`
already worked around this; the new actions do the same. It is a trap for
anyone writing a redirect in that controller and it is not written down
anywhere but here and a comment.
