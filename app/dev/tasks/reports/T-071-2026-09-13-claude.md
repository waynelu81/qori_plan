# T-071 — report

## Outcome

Pressing "Get access" on a priced Series now opens Stripe's payment page.
The controller answers an Inertia request with `Inertia::location()`, a 409
carrying the session URL for the client to visit, instead of a plain redirect
that an XHR could not follow across origins. A request without the Inertia
header still gets the ordinary redirect. `T-062` carries a line so the
connect button does the same when it becomes an Inertia POST.

**None.**

## Departures

None in the code. **On the owner's machine**, the local `.env` webhook
secret did not match the Stripe CLI's `listen` secret, so a completed payment
would have been rejected as an invalid signature and no access granted.
Replaced with the CLI's value, without printing either. Recorded on the task
because the next person will hit it too.

## Found, not fixed

- Two `stripe listen` processes are running on the owner's machine, one with
  an event filter and one without. Each event will be delivered twice;
  fulfilment is keyed by session id, so the second delivery should be a
  no-op, but one listener is enough.
- The Series slug is `hoew-to-start` because the title was typed that way
  and later corrected; slugs are kept on rename by design (`GroupService`
  says the same for Groups). Expected, and worth knowing when reading URLs.

## Evidence

None needed. Stripe's session list is reproducible from the connected
account id in the task's Why.
