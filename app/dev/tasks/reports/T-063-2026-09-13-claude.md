# T-063 — report

## Outcome

There are two doors to one column. An owner with a Stripe account already can
choose "Connect the Stripe account I have": Qori puts a nonce and the Group in
the session, sends them to Stripe's authorize page, and when Stripe hands them
back under `/u/payouts/stripe/return` with a code and the same nonce, the code
is exchanged for the id of the account they chose and stored where a created
account's id goes. Declining at Stripe comes back as a note, not an error. A
nonce that does not match is refused before anything is exchanged. The other
door, the country select and "Create a new Stripe account", is `T-062`'s POST
unchanged. Every account is now read back through `GET /v1/accounts/{id}`
whichever door it came through, and `ConnectAccount` reads the v1 booleans;
that also retires the v2 reader's wrong answer about a finished account.
The page has a fourth state, `incomplete`, for a form the creator never
finished, which says to pick up where they left off instead of "nothing to
do". Disconnecting deauthorises at Stripe when the OAuth client id is
configured, and only forgets when it is not, so nothing here depends on OAuth
being enabled.

## Departures

**The first door is withheld until the client id is configured.**
`existingLabel` is null without `services.stripe.client_id`, and the page
shows only the create door. The spec showed both buttons always; a link that
lands on Stripe's "invalid client_id" page is worse than no link. The
disconnect guard already made the same choice.

**`unwrap()` reads `error_description`.** OAuth puts a code in `error` and
the words beside it, and the trait's error path would have logged "no
message" for every OAuth failure.

**`stripeOAuth()` does not retry.** An authorization code is single-use; a
retry after a request that reached Stripe is a guaranteed `invalid_grant`.

**`PayoutsService::read()`** is a private helper both doors use, so `T-072`'s
prefix memory runs on an account that was signed over as well as on one that
was created.

**A declined landing also clears the session nonce**, so a stale one cannot
be replayed later.

**The stop-and-rewrite of `T-062`** happened under this task's request; its
own report says how.
