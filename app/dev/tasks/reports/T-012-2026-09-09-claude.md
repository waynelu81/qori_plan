# T-012 — report

## Outcome

`php artisan qori:reachability` lists GET routes nothing links to and public
service methods nothing calls from outside their own class. Qori had shipped
three unreachable capabilities, each found by a person happening to read the
code; this is the same audit as a command that can be run again.

First run: **0 unreachable routes, 2 service methods**. Both methods are called
only by their own class — `public` where `private` would do. One of them,
`SuppressionService::suppress`, is the end of a chain nobody enters: its two
callers have no callers outside tests, because nothing feeds the suppression
list from a real provider. The scanner found the shape of a missing integration
by noticing where a chain stops.

| What                       | How                                         | Result                |

| `composer ci:check`        | Full gate, cleared PHPStan cache            | Green                 |

**Could not verify:** that the tool would find a genuinely unreachable _feature_,

on a synthetic orphan; the real run reports nothing, and "nothing" is only
meaningful if you also read the limits below.

## Where the specification was wrong

| Section    | Said                                                                           | Actually                                                                                                                                                                                                       |
| ---------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Acceptance | "The known cases appear: Connect onboarding, campaigns, `payment_fulfilments`" | None of the three can appear. Connect onboarding **is** linked now (the Payments page was built after the spec). Campaigns have no routes at all. `payment_fulfilments` is a table, and Scope excludes models. |

This was the interesting one, and it is worth the space. **Two of five workers
who ran this task stopped and re-scoped it on the strength of that Acceptance
line; three completed it.** All five were reacting to the same defect. Nothing
about what had to be _built_ was wrong — the Scope section was right throughout.
`PROCESS.md` now says which of the two is the contract, because a plan where one
task can be both correctly finished and correctly abandoned cannot divide work.

## Departures

Two tests beyond the six specified: one asserting the allow-list carries a
reason for every entry, one asserting a hand-built URL counts as a link.

The URI pattern was widened during the build. The first version excluded quotes
from a path segment, which meant `` `/g/${group.slug}/series` `` did not match
and four live routes would have been reported dead on day one. A tool that is
wrong on its first run is a tool nobody runs twice.

## Found, not fixed

**The method half of this scanner is weaker than it looks, and the findings doc
says so.** It counts `tests/` as a caller, which means a capability with tests
but no UI — exactly what this stream exists to catch — will not be reported. It
is accepted because the alternative reports most of the codebase. The route half
is what catches an unreachable feature; the method half only catches `public`
that should be `private`.

**A clean run is not a clean bill.** Campaigns were never routed at all, and a
tool that looks for unreachable routes cannot see a feature that has none.
