# T-023 — report

## Outcome

Every closed-value attribute on every model is a backed enum under
`app/Models/Enums/`. Eighteen enums replace fifty-seven string constants across
fifteen models, the models cast them, and roughly three hundred call sites in
`app/`, `tests/` and `database/` now compare enum instances rather than strings.
Two families are deliberately still strings: `subscription_status`,
`SubscriptionPrice::INTERVAL_*` and `SubscriptionCoupon::DURATION_*` are
Stripe's vocabulary, and enumerating them would make Qori's copy of Stripe's
state machine look authoritative.

The refactor is worth more than the type safety, because of what it found. The
task's Why cites one value — `Series::STATUS_ARCHIVED` — declared and unused for
a month, and argues that `cases()` would have shown it. Written as a test, that
argument found **ten more**: two campaign types, a Group status, four campaign
recipient statuses, a suppression reason, and the two placeholders that were
already known. Every one is a state the product can describe and cannot reach.

**if any production row holds a value outside its enum, the page that reads it
will 500.** A pre-deploy `SELECT DISTINCT status` per column would settle it and
I could not run one.

by eye and by a PHP test asserting the component no longer contains the words.

## Departures

**Two service signatures now take enums, and that deleted two error paths.**
`SeriesService::addEpisode()` takes `EpisodeType` and `EpisodeProvider`;
`CampaignService::draft()` takes `CampaignType`. Both used to open with an
"unknown value" guard throwing `errors.series.unknown_episode_type` and
`errors.campaign.unknown_type`. PHP refuses those calls before the body runs
now, so both branches were unreachable and both lang keys had no thrower. Both
removed. Flagging it because deleting an error message looks like a behaviour
change and is the opposite: it is the type system taking over a runtime check.
Neither key was ever tested, which is itself the same finding in miniature.

**`ResolvesMedia::provider()` returns `EpisodeProvider`, not a string — and it
was returning the wrong constant family.** `DropboxStorage` and `VimeoVideos`
returned `Connection::PROVIDER_*` while `PlaybackTicketService` compared the
result against `$episode->provider`. Two different constant families, agreeing
only because both spelled it "dropbox". The enums made it a type error.
`EpisodeProvider::connection()` is now the one explicit crossing between them,
and Qori's own storage is what proves they are different things: it has a media
resolver and no connection at all.

**The design-review seeder was writing undeclared values.** `consent_source`
held `invite_form` and `checkout`; `AccessService` only ever writes `peer` or
`creator`. The cast refused them on the first run. Fixed in the seeder, because
the fixture had drifted from the product it exists to photograph — not by
widening the enum, which would have enshrined the drift.

**`EmailSuppression::$attributes` keeps a raw string.** `$attributes` defaults
are written straight into the insert and the cast never runs over them, so
`SuppressionScope::Marketing` there would try to bind an object as a column
value. It reads `SuppressionScope::Marketing->value` — the enum for the fact,
`->value` for the storage. This is the trap `CLAUDE.md` records for jsonb
defaults, arriving in a second form.

**HTTP test payloads send `->value`.** Symfony's `InputBag` rejects a non-scalar,
so `post([... 'type' => EpisodeType::File])` is a 500 rather than a request.
Factory and `create()` arrays keep the enum, where the cast handles it. The
distinction is real and worth stating: an enum is fine anywhere Eloquent is
between you and the column, and never on the wire.

**`PeerStatus::rank()` and `outranks()`.** `Peer::promoteTo()` ranked statuses
with an array literal keyed by the constants, and PHP has no enum array keys.
The ranking moved onto the enum, which is where an order among statuses belongs.

## Found, not fixed

- **Ten enum cases nothing can produce.** Listed in
  `ModelEnumTest::test_every_enum_case_is_reachable_from_its_model` with the
  task that owns each: `T-014` for the two campaign types and `GroupStatus::Archived`,
  `T-017` for the four recipient statuses, `T-013` for `SuppressionReason::Manual`,
  `T-010` for `SeriesStatus::Purged`. The campaign ones are the loudest:
  campaigns have a service, a model, a recipient table and **no route at all**,
  and only `Launch` is ever drafted, by a test. That is `T-012`'s shape exactly,
  found by a different instrument.
- **The §8 provider map is still written twice.** `EpisodeType::allowedProviders()`
  is now its one authority in PHP, and `share/series/Show.vue` still carries a
  hand-copied `Record<string, string[]>` of the same rule with a comment saying
  it mirrors the PHP. One prop from `SeriesController` would delete it. Left
  alone deliberately: the Code section names the status label and nothing else,
  and this task is already large enough to be hard to review.
- **`EpisodeType` and `EpisodeProvider` have no `label()`.** Their labels live
  in `Show.vue` and have no PHP consumer, so adding one would create the exact
  "declared and read by nothing" shape this task exists to remove. Whoever needs
  them server-side — mail, a certificate, `T-005` — should move them then.
- **The Vue side could take a union type.** `status: 'draft' | 'published' | …`
  would give TypeScript the same protection PHP just got. Cheap, and it belongs
  with `T-006` rather than here.
- **A pre-deploy check on production data.** See "could not verify" above.
