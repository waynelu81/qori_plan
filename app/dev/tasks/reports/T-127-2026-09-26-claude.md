# T-127 — report

## Outcome

A creator can now correct a live Episode's recording and say when there
isn't one. Each recording line on the creator's row has **Hide**, and a
hidden one reads "Hidden from Peers · Show again"; hiding keeps the row, so
Show again puts it back as the same part, and a Peer told "Part 2" still
finds Part 2 after Part 1 is hidden. Once a Peer can see one, the paste
toggle reads **Add another link**. A session that is over with nothing to
watch offers **There's no recording for this session**; the Peer's card then
reads "Live only" and "This session wasn't recorded.", final, with "Join
again" only while Join's grace lasts, and **Undo** puts it back. Forty-eight
hours after the scheduled end with nothing visible, the Peer reads "No
recording has been added for this session yet. You'll get an email if one is
added." and the creator reads the same fact with the hours from config and
the two ways out. A "Live only" session reads `not_recorded` once Join closes
with nothing to undo. "Join again" now also shows above Watch in the grace,
so a recording pasted mid-session no longer takes away the way back into an
overrunning class.

## Departures

- **A recording made visible withdraws the declaration.** `unhide()` clears
  `not_recorded_at` when its row becomes visible, and `paste()` when it writes
  one, under the Episode's row lock — see the table above; the flow-doc writer
  found the gap.
- **The badge follows `stateFor()`'s order on both pages**: "Recorded" while a
  Peer can see a recording, whatever the switch said, and otherwise "Live
  only" for the switch or a declaration. Left alone, the card printed
  "Recorded" beside "This session wasn't recorded.", and its own tick moved a
  declared session to `waiting` when Join closed. The creator's Edit form
  keeps the switch's own value, so an edit never flips it.
- **"Join again" in `ready`**, above the Watch list, while the grace lasts —
  `T-126`'s report sent it here. `LiveSessionCard.vue`'s only edit.
- **A "Live only" session after its end** has no Undo on the panel (it would
  clear nothing) and keeps `T-126`'s paste toggle, because a recording pasted
  anyway is `ready`.
- **`declareNotRecorded()` checks the visible recordings under the row lock**,
  which a paste takes too, and keeps the first `not_recorded_at` when said
  twice.
- **`hide()` and `unhide()` log a line** when they change a row, as `paste()`
  does.
- **Both controllers take their service by constructor**, the house rule for a
  primary service; the spec had method injection. `RecordingController` moves
  `T-126`'s `store()` onto it.
- **`records()` is `!== false`**, `stateFor()`'s own reading, where
  `SeriesController` had `(bool)`: the same value for the booleans every
  writer stores.
- **Six cases beyond the 16** in `RecordingStateTest`: the badge on both
  pages (17), a second declaration keeping the first moment (18), the paste
  route refusing a File Episode through `liveEpisodeOf()` (19), a recording id
  of another session (20), and the two withdrawals (21, 22). Every negative
  assertion in the file was made to fail once in a scratch copy before it was
  trusted. Case 3 watches once before the hide, as its control.
- **`withLockedContent()`'s docblock** said no current Group is needed; its
  lock needs none, but the two callbacks that read recordings do, and it says
  so.

## Found, not fixed

- A test's requests share one application, and `SetCurrentGroup` fills the
  scoped `CurrentGroup` with a bare `set()`, so a Peer request after a
  creator request in the same test runs with the creator's Group still
  current — which hides a missing `runFor()` on the Peer surface, the bug that
  surface is most exposed to. `RecordingTest` and `RecordingStateTest` work
  round it by hand → draft T-203
- A Peer's Watch label and `paste()`'s numbering count every row, and
  `T-143`'s held rows (`published_at` null) would count too: a Peer could read

  writes one → T-143
