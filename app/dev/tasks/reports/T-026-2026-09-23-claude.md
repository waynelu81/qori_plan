## Where the specification was wrong

| Section | Said | Actually |
| ------- | ---- | -------- |
| Code    | `store()` redirects to `route('share.series.show', […]).'#new-episode'` | A redirect after an Inertia `POST` is followed by the client, which does not act on the fragment. `Show.vue` scrolls to the form itself on mount when it arrives with the query and no Episodes. The fragment stays in the URL for a full-page load. |
| Code    | `Show.vue` sets the form's first kind and title | Inertia's `<Form reset-on-success>` puts every field back to the value it held **when it mounted** and does not tell a `v-model`, so after the first save the title reverted to "Part 1" and the kind select could disagree with the page's `type`. The fields are re-mounted on the form's `reset` event with the next kind and title. |
| Copy    | Sixteen keys | Seventeen: the radio group needs a legend, `onboarding.first.shape_label`, "Its shape". |

## Departures

- **`store()` sends anyone already past the screen to the dashboard with
  nothing made**, so a double click or a second tab cannot make a second
  Series on a plan that would allow it. Not in the spec; one line.
- **The redirect query is built without `array_filter`**, and the numbered
  title comes through `Terminology::line()` rather than `__()`, which PHPStan
  refused as `array|string|null`.
- **Tests: two removed, five renamed.** `SetupTest::test_the_setup_page_offers_the_name_form`
  (the name form is gone; case 2 of `FirstSeriesTest` covers the page) and
  `SetupStepsTest::test_an_owner_resumes_at_the_first_unfinished_part` (there
  is no resuming). Renamed to say what they now arrange: `SetupTest`'s
  `…unnamed_group…` to `…with_no_series…`, `SetupStepsTest`'s
  `…lands_on_the_name_part` to `…lands_on_setup`, and two in
  `OnboardingHomeTest`. `test_the_frame_counts_the_parts` counts parts two and
  three only. The spec expected more `SetupTest` rewrites; most passed
  unchanged because a fresh owner also has no Series.
- **`docs/flows/onboarding.md` was rewritten more than the Files row
  suggested**: the record section and the `setup`-flag paragraph now say what
  still reads them and that `T-195` retires them.

No file outside the Files table was touched; `resources/js/routes` is
regenerated and gitignored.
