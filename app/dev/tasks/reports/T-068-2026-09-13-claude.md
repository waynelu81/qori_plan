# T-068 — report

## Outcome

A new creator is asked to name their Group before anything else. Confirming
the address, signing in, and choosing to start sharing all land an owner whose
Group has no chosen name on a page with one question on it, in the same shell
sign-in uses and with no sidebar. It shows the name Qori made up, the name
field, the timezone the dashboard card already asks for, and a line saying it
can be changed later. Saving goes to the Group's home with the existing
"called … now" toast. An admin is never sent there, an owner who has answered
is never sent there again, and somebody who navigates away is not trapped:
the dashboard's own name card still catches them. The onboarding stream is in
`PLAN.md`'s table, and `T-026` no longer includes the name step.

## Departures

**`startSharing()` refreshes the user before asking `SignInLanding`** so the
Group just created is visible to `accessibleGroups()` on the same request.

**Three tests changed** that the spec said would not: two in
`EmailVerificationTest` and one in `VerificationDetourTest` asserted the
fallback URL carried `?verified=1`, which nothing read and which the new
landing drops. One in `OneGroupPerPersonTest` (this morning's `T-065`)
asserted "start sharing" lands on the dashboard; it lands on setup now, which
is the point.

## Found, not fixed

- Pressing Enter in the name field did not submit the form in the browser;
  clicking Save did. That is `GroupNameForm`, which the dashboard card has
  used all along, and it deserves a look of its own.
- The Save button says "Save". On this page "Continue" would say what happens
  next; the button lives in the shared form and this task did not add copy.
- Pricing, still: with an empty database the billing and public pricing pages
  list no plans until something seeds `subscription_prices`.
