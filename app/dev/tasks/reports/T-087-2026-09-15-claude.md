# T-087 — report

## Outcome

Sign-in asks for the address on its own now. The page opens with the email
field and **Next**, and nothing else in the composition; passkey and the exit
to registration sit below it as before. Next moves on in the browser for any
well-formed address and makes no request, so it tells nobody whether an
address has an account. The second step shows the address with **Use a
different email**, then the Password / Email link chooser `T-077` built, with
focus on the chosen method's first control. A wrong password keeps the person
on that step with the error under the address. Use a different email, from
that step or from "Check your email", returns to the first step with the
address kept and the cursor in it.

**Could not verify:**

- **Enter as Next.** The Browser pane's key presses, `Return` and `Enter`,
  never triggered a form submission on either step, including the password
  panel `T-077` shipped, which submits on Enter in an ordinary browser. So
  every step was driven by clicking. The first step is a native form with one
  submit button, which is what makes Enter submit it, but that was not
  observed here.
- **A successful password sign-in and the 2FA challenge in a browser.** No
  account was created for this; the suite covers both.
- **Password managers.** Whether a manager fills and saves against the
  hidden `autocomplete="username"` field on the second step was not driven.
- **The light theme.** The pane rendered dark and only dark was looked at.
  The change adds one bordered row in existing tokens.

## Where the specification was wrong

| Section       | Said                                                             | Actually                                                                                                                                                                                                |
| ------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Preconditions | "one factory user with a known password for the browser walk"    | Not needed. An address with no account reaches every state but a successful sign-in, which the suite covers, so no account was created                                                                  |
| Code          | Named the address row's `data-test` and nothing about its layout | A grid item does not shrink below its content, so `truncate` alone never applied and a long address widened the step past a phone's screen. `min-w-0` on the block and on the row is part of the design |

## Departures

- **`min-w-0` on the address block and row, `title` on the address, `-my-1
py-1` on Use a different email.** The layout defect above, found by the
  375px walk. The padding takes the button from 20px to 28px tall without
  changing the row's height. Same file.
- **A comment was reworded so a test could count.** The first step's comment
  named the field's `type` attribute literally, and
  `test_the_page_has_one_email_field` counts that string, so the comment read
  as a second field.
- **`T-006` gained a line under Notes**, the finding below. Listed under
  **Added during execution** in the task.

## Found, not fixed

- **`LinkSent`'s "Use a different email" is still inline English**, while the
  same words on the second step now come from `auth.sign_in.change_email`.
  `LinkSent` was out of scope; the key is there for whoever converts it. → T-006
- **The card moves when the step changes.** The auth layout centres its
  content vertically, so Next shifts the logo and the fields by the
  difference in height, as switching between Password and Email link already
  did after `T-077`. → decided: it is the shared auth layout's centring, every
  auth page has it, and nobody has said it bothers them; changing it is a
  layout decision for the design stream, not a sign-in one
