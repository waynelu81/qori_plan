# T-061 — report

## Outcome

Creating a connected account sends the owner's address under `contact_email`,
the name Stripe recognises, instead of `peer_email`, the name the domain
rename gave it by accident. That is the whole change: one key. A creator who
clicks "Connect with Stripe" now gets a Stripe account created and is sent to
onboarding, where before every click since 9 September was answered with an
upstream error and the local log filled with Stripe's refusal.

would create a real test-mode account on the owner's Stripe platform, which
is a side effect the owner did not ask for in this task, and `T-062` needs the
same round trip with a different payload and specifies it as a precondition.
The evidence that this key is the one Stripe wanted is Stripe's own error text
and the v2 create reference, which lists `contact_email` and nothing named
`peer_email`.

## Found, not fixed

- The account is still created with a pre-filled country and a requested
  capability, and the button is still a GET that writes. `T-062`.
- There is no way to disconnect. `T-064`.
- There is no way to connect an account the creator already has. `T-063`.
- `ConnectOnboardingTest` asserts the payload field by field, which is right,
  and that is how the email came to be the one field nobody asserted. A
  rename that touches vendor parameter names has no test that can catch it in
  general; the honest guard is the grep in Notes on the task, run by whoever
  does the next rename.
