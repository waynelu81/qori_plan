# T-111 — report

## Outcome

The storage Qori itself provides is now `EpisodeProvider::CloudflareR2`
(`cloudflare_r2`), and its code is `App\Integrations\CloudflareR2\CloudflareR2Storage`
and `CloudflareR2Uploads`. A migration renames every stored `qori_s3`, and rolls
back. A creator still reads "Qori storage" on the Episode form and in the
Episode list. `Episode::isSelfHosted()` now asks the provider, so a second
Qori-hosted offering is added in one place.

**For the owner:** the development database still holds 18 Episodes with
`qori_s3`. Run `php artisan migrate` there; until then those Series pages fail
to load their Episodes. On a production deploy, `migrate --force` runs the same
update. If an old instance writes `qori_s3` in the moment before the new code
serves, running `migrate` again does nothing, because the migration is
recorded: run the update by hand instead
(`DB::table('episodes')->where('provider', 'qori_s3')->update(['provider' => 'cloudflare_r2'])`),
and do not roll back for it.
