# T-037 — report

## Outcome

Each settings page now has one level-one heading, the visible one the layout
emits. The three pages keep their specific context as an `<h2 class="sr-only">`,
so somebody navigating by headings reads "User settings" and then "Profile
settings" underneath it rather than two documents stacked.

Nothing visible changed. That was the point.

## Verified

| What                     | How                                                           | Result                                  |
| ------------------------ | ------------------------------------------------------------- | --------------------------------------- |
| The three pages          | `grep` for `<h1` under `resources/js/pages/settings`          | None. Three `<h2 class="sr-only">` left |
| The layout still has one | `HeadingsTest` second case, through `PageHeader`              | Passes                                  |
| Nothing visible moved    | `sr-only` on all three before and after; only the tag changed | Unchanged by construction               |
| Settings at 375px        | Browser, dark theme, `/u/profile`                             | "User settings" reads as the only title |

## Where the specification was wrong

Nowhere. Three tag changes and two test cases, exactly as written. The spec's own
observation is the useful one: this finding is source evidence and does not
appear in a screenshot, which is why it survived a redesign and two review
passes.

## Departures

- **The second test asserts more than the spec sketched.** It checks both that
  the layout still renders `PageHeader` and that `PageHeader` still emits an
  `<h1>`. One without the other can be satisfied by deleting the visible heading,
  which would empty the first case and leave the section with no level-one
  heading at all — a worse document than the one being fixed.

## Found, not fixed

- **`AuthSimpleLayout` emits an `<h1>` too**, and the auth pages do not add a
  second, so they are correct. Noted only because the first test walks
  `pages/settings` alone and would not see it if that changed.
- **Heading structure elsewhere is unread.** The Scope says so. The test is
  scoped to the settings directory deliberately, rather than failing across the
  product on a rule nobody has checked.
