# T-081 — report

## Outcome

A fresh clone reaches a green gate with `composer setup`: it starts the
containers and waits for them, copies `.env` _before_ `composer install` (the
order that was in the script failed on a clean clone — see below), creates the
five test databases if the volume predates them, migrates, generates Wayfinder
before the build, and points `core.hooksPath` at `.githooks/`. Every checkout
on a machine now has a test database of its own: the container holds
`qori_testing` and `qori_wt1_testing` to `qori_wt4_testing`, `Tests\TestCase`
accepts `_testing` and paratest's `_testing_test_N` and nothing else, and
`DB_DATABASE=qori_wtN_testing` in front of any test command is the whole
recipe. `php artisan test --parallel` runs the suite in under a minute against
twelve per-process databases. Pre-commit refuses a commit with a Pint or
formatter violation and applies the board rules when planning changed;
pre-push runs Pint, PHPStan and the fast tests, with `QORI_SKIP_PUSH_TESTS=1`
as the documented way out. CI runs Postgres 18 like everybody else, cancels a
superseded run, gives up after fifteen minutes, caches Composer and npm, and
clears the PHPStan result cache inside `types:check` so the local pass is the
one CI sees. `.env.example` names every `QORI_*` key `config/` reads and a
test keeps it that way. The README is the entry point it was not.

## Departures

- **Pre-commit runs Pint on the staged PHP files, not `--dirty`.** `--dirty`
  reads `git status` and includes unstaged edits, so a half-finished file
  outside the commit would refuse a commit that did not contain it. Same
  check, right set of files.
- **`engines.node` is `>=22`, not `22`.** The owner's machine runs Node 24 and
  npm warns on every install when `engines` excludes the current version;
  `.nvmrc` says `22` and CI reads it from there.
- **`qori:testing-databases` derives the names from the connection's database
  name** (`qori` → `qori_testing`, `qori_wt1_testing` …) rather than
  hardcoding them, and refuses to run from a database that already ends in
  `_testing` so a worktree run cannot produce `qori_wt2_testing_testing`.
- **`.env.example`'s database comment block was rewritten**, not only the
  duplicate line removed: it contradicted itself (a note saying the variable is
  `DB_URI` beside one saying not to use `DB_URL`, and a reference to Atlas).
  `config/database.php` reads `DB_URL`; the comment now says so once.
- **`setup-node` reads `node-version-file: .nvmrc`** instead of a second copy
  of the version, so the number lives in one place.

## Found, not fixed

- **`composer setup` rotates `APP_KEY` on every rerun.** `key:generate`
  overwrites an existing key without asking outside production, so running
  `setup` twice invalidates every session and encrypted value in the local
  database. Pre-existing; a guard around that step belongs to whoever next
  touches the script.
- **Three test classes are outside PSR-4**: `Tests\Feature\Accesses\*` live in
  `tests/Feature/Access/`. Composer warns on every dump-autoload. Needs a
  task, or a rename in passing by `T-083`'s neighbour.
- **`.prettierrc` is dead config.** `vp check` reads the `fmt` block in
  `vite.config.ts` (`printWidth: 80`); `.prettierrc` says 150 and lists
  plugins that are not installed. Nothing reads it. `T-082` owns the
  convention docs; the file itself is nobody's.
- **`docs/tinker/README.md` and `docs/planning/engineering-runbook.md`** still
  describe one `qori_testing` for everyone. `T-082` and `T-080` own them.
- **`CLAUDE.md`'s PHPStan-cache paragraph** is now wrong — `types:check`
  clears the cache — and is `T-082`'s to delete, as the spec says.
