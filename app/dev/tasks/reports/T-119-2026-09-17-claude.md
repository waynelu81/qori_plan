## Departures

- `tests/e2e/tsconfig.json` sets `types: ["node"]` rather than the root
  `tsconfig.json` gaining `tests/e2e/**` in `include`. Adding Node's globals
  to the root would have changed `setTimeout`'s return type under every Vue
  file. The Files table listed the file; this is the reason it exists.
- `PHP_CLI_SERVER_WORKERS=1`, above.
- The command uses `$this->error()` for a refusal rather than
  `components->error()`, so the PHPUnit cases can match a substring of one
  line: the component box wraps long messages at the terminal width and the
  tests would have depended on it.

## Found, not fixed

- `compose.yaml`'s `qori-mailpit` container cannot start on this machine:
  another project's container named `mailpit` holds 1025 and 8025, and the
  run — like `qori:mail:check` — used that one. Both are v1.31.1 and the
  inbox is shared, so the run empties the other project's inbox too. A
  dedicated port pair, as Postgres has with 5433, is the same fix for the same
  reason → decided: the owner chose 5433 for Postgres after the identical
  collision; whether Mailpit gets one is theirs to call, and nothing in
  `compose.yaml` is wrong on a machine without the other project
- `php -S` with `PHP_CLI_SERVER_WORKERS` above 1 forks workers that survive a
  SIGTERM to their parent. `artisan serve` has the same exposure — its
  `stop()` on Ctrl-C reaches only the parent — and a developer who has run it
  with the `.env` default may have workers still holding 8001 after it exits
  → decided: not Qori's code, and `artisan serve` restarts cleanly on the
  next `php artisan serve` because the orphans die when the terminal does;
  the e2e command pins one worker, which is the only place it matters
- The Peer half of the loop — access, the Peer opening an Episode, progress,
  the certificate — has no journey yet, and the beta gate's first line asks
  for both halves → decided: the task's Out list named it as the next journey
  once this one runs; it is a `workflow` draft for the owner to open when the
  Peer flow's own tasks (`T-043`) have settled, because a journey written
  against a flow that is about to change is a journey rewritten twice
