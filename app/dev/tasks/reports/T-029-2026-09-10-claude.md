# T-029 — report

## Outcome

A live session can now be given a time, and the time is the one the creator
meant. The Episode form shows a date-and-time field for a live session and only
for a live session, labelled with the Group's zone; what is typed is read in
that zone and stored as a UTC instant; and every surface that shows a session
time now names a zone beside it, which none of the three did before.

The bug this closes was not "the field is missing". `episodes.starts_at` was
validated with `['nullable', 'date']` against an application timezone of UTC, so
the obvious way to add the field would have read a Melbourne creator's 9am as
9am UTC and told their Peers 7pm with complete confidence. A missing field stops
one person; a wrong one misinforms everybody. The assertion that proves it is
one line: Group in `Australia/Melbourne`, post `2026-10-01T09:00`, stored value
`2026-09-30T23:00:00+00:00`.

A live session is also refused outright in a Group that has never answered the
timezone question — not one that _resolves_ to UTC, one that has never been
asked. That is the single place in the product that insists on an answer rather
than taking a default, and it earns it: the alternative is not an unconfigured
product, it is a confidently wrong one.

## Where the specification was wrong

| Section | Said                                                               | Actually                                                                                                                                                                                                                                                                                                            |
| ------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Code    | `SessionTime` "renders the viewer's local time and names the zone" | The obvious implementation throws. `dateStyle`/`timeStyle` cannot be combined with `timeZoneName` — ECMA-402 raises `TypeError: Invalid option : option` — and formatting during hydration took the **whole page** down, blank. All three surfaces used the shorthand pair, which is why none of them named a zone. |
| Code    | `starts_at` gets `after:now`                                       | Correct only after the conversion. On the raw input it compares a naive local string against a UTC instant and refuses valid future times for anybody west of Greenwich. Moving the conversion into `prepareForValidation()` fixes the rule and the storage in one place.                                           |
| Code    | `$series->group?->timezone === null`                               | Right in intent, and it has to be the Group's **own** zone rather than `timezone()`, which falls back to the owner's and then to UTC. `hasChosenTimezone()` — added in T-024 for the form — is the predicate. Written the other way the guard would never fire for a Group with an owner who had a zone.            |
| Copy    | `errors.series.timezone_required` uses `:group` and `:peer_plural` | `AppException` resolves lang with plain `__()`, which does not fill noun placeholders. Every other line in `errors.php` avoids them for that reason. Both throw sites now pass `Vocabulary::replacements()`, so the line works and a Pro Group's own noun appears.                                                  |
| Copy    | `series.session_scheduled`                                         | Listed with no consumer named. Used as the store toast for a live Episode, which is the one place it earns its keep: what the creator typed was local and what was stored is an instant, and being shown the result is how they tell those agree. Needed `EpisodeController`, not in Files.                         |
| Files   | Ten paths                                                          | Three more: `EpisodeController` for the toast above, and two existing test files whose Groups had no timezone and whose live Episodes are now refused.                                                                                                                                                              |

## Departures

**An inline warning on the form, ahead of the refusal.** The spec puts the rule
in the request and the service. Both refuse _after_ somebody has typed a title
and pasted a join link. The builder now says it before they start, when the kind
is set to live and the Group has no zone. The server still refuses — this is the
notice, not the rule.

**The service also refuses a past time.** `errors.series.starts_in_past` is in
the Copy table with a message and a resolution, which makes it an `AppException`
key rather than a validation message, and it needed a thrower. Same shape as the
§8 provider rules: the request puts the message on a field, the service makes it
true for every caller.

**Two existing test files changed.** `SeriesServiceTest` and `EpisodeRoutesTest`
each add a live Episode in a Group with no timezone, which is now refused. Both
were given a zone rather than being worked around, and the refusal has its own
coverage in `LiveSessionTest` rather than living as a broken expectation in
theirs. Worth flagging because a reviewer sees two unrelated test files in the
diff.

## Found, not fixed

- **`SessionTime` renders differently on the server and the client.** Vite SSR
  formats in Node's locale and zone, the browser re-formats in its own, and Vue
  logs "hydration completed but contains mismatches". Visually correct after
  hydration, and true of the three formatters this replaces, so it is not a
  regression — but it is noise in the console and it belongs to `T-025`, which
  is the task that owns how times are displayed.
- **`EpisodeController::update()` cannot change a start time.** It validates
  `title` and `is_preview` only. That is why
  `test_editing_an_episode_keeps_the_time_it_had` passes — the time survives
  because nothing can touch it. A creator who schedules a session for the wrong
  hour has to delete the Episode and add it again. Needs its own task; it is a
  second form and a second conversion, not a line.
- **The seeder writes `starts_at` straight onto the model**
  (`DesignReviewSeeder`), bypassing `addEpisode()` and therefore both guards.
  Harmless for a seeder, and worth knowing before anyone treats the service as
  the only path.
- **`timeZoneName: 'short'` renders "GMT+10" rather than "AEST"** under this
  browser's locale. Unambiguous, and arguably better for a reader in another
  country, but it is not the string the spec's example used.
