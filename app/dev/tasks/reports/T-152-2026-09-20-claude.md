# T-152 — report

## Outcome

Adding an Episode whose item id means nothing without the creator's own
account is now refused where the creator can act on it, instead of producing a
published Series that does not open and telling the Peer about it. Dropbox is
the only account-bound provider today; a Qori-hosted file, a Vimeo video and a
live Episode with a pasted join link are all still added with nothing
connected. A revoked row and a row marked for reconnect each count as not
connected, because the guard reads `Connection::isLive()` rather than the
row's existence.

The two sentences differ by what the creator can do about it. A provider whose
connector is not bound yet — Dropbox, until `T-096` — gets
`errors.series.provider_not_available`, which is final and names no provider.
One whose connector is bound and whose Group simply has no live row gets
`errors.series.provider_not_connected`, which names the provider and points at
Integrations.

## Where the specification was wrong

1. **`EpisodeService` already has a constructor.** The spec says "the class
   having none today"; it takes `LiveSessionService` and `MaterialService`.
   `ConnectionService` was added as a third promoted dependency. Nothing
   constructs the class with `new`, so no caller changed.
2. **`provider_not_available` is not as final as the spec believes.**
   `AppException::resolution()` falls back to the `ErrorCode`'s own key, so an
   `invalidRequest` carrying no `resolution` still renders
   `errors.invalid_request.resolution` — "Check what you entered and try
   again." Omitting the key is as final as this framework allows, and it
   matches every other deliberately-final key in the file
   (`series.already_purged` inherits `errors.not_found.resolution` the same
   way). Worth knowing before somebody walks it: the toast on a refused
   Dropbox add carries that generic second sentence.
3. Three stale line citations, all harmless: `guardEpisodeType()` is at
   `:390`, the `replacements()` pattern at `:121`, and `PlaybackTest`'s case
   at `:164-175` with its live connection at `:113-118`.

## Found, not fixed

- `lang/en/connections.php` has no `providers.dropbox.name`, so
  `provider_not_connected`'s `:provider` currently interpolates the literal
  key rather than a name. It is unreachable in production today — nothing
  binds a Dropbox connector, so `connectorFor()` is null and
  `provider_not_available` fires instead — and it only appears in tests that
  bind `ConnectsNothing`, which assert the lang key rather than the prose. The
  name arrives with the connector, and `T-096` adds both in one change; a line
  saying so is now in that draft. → T-096
- The generic resolution sentence on a deliberately-final error, described
  under "Where the specification was wrong" above. It is the framework's
  behaviour for every final error in the app, not this task's.
  → decided: changing `AppException::resolution()`'s fallback would alter
  every final error in the product at once, which is a decision record and
  not a bullet in a report; the copy rule in `CLAUDE.md` should say what
  "final" actually gets, and that belongs with whoever next amends it.
