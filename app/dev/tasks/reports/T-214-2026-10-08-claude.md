# T-214 — report

## Outcome

Telescope is now a local debugging aid that nothing else can see.
- Its migration moved to `database/migrations/local/`, which only
  `TelescopeServiceProvider` loads, and that provider is registered only in
  `local`. A production boot's `migrate --force`, the tests and
  `migrate:status` under `testing` no longer know it exists.
- It masks OAuth secrets and tokens, sign-in and 2FA codes, the CSRF token,
  cookies and Stripe's webhook signature in every environment. The stub used to
  return early in `local`, the only place Telescope runs, so it hid nothing
  there.
- Its storage connection defaults to `pgsql`.
- It ignores `wayfinder:generate`.
- `qori/CLAUDE.md` says what it is, where it runs and where its migration lives.

The 5 October install it finishes (`laravel/telescope` and
`barryvdh/laravel-ide-helper` as dev dependencies, Telescope kept out of package
discovery) is unchanged.

## Found, not fixed

- `qori:e2e` serves its run with `APP_ENV=local` (`EndToEndCommand.php:260`), so
  Telescope registers in the journey's server and records its traffic, and
  `migrate:fresh` there builds Telescope's tables in `qori_e2e`. This is
  harmless: that database is rebuilt every run, and the secrets are now masked.
  → decided: leave it; adding `TELESCOPE_ENABLED=false` to the run's
  environment is one line if its overhead ever shows in the journey's timings.
- The dev database's `telescope_entries` still holds rows recorded before this
  task, including token exchanges in plain text from the 5–6 October sessions.
  → decided: the owner's local data; `php artisan telescope:clear` empties it,
  and the Notes say so.
