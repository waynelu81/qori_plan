# T-016 — report

## Outcome

There is a local inbox, and every transactional message has now been read.
`docker compose up -d` brings up Mailpit beside Postgres; `qori:mail:check`
sends all six messages through the paths the application actually uses, reads
them back out of Mailpit's API, and reports on each one.

```
 You're in: Mail Check Series .. ok
 Your email address was changed .. ok
 Confirm your new email address .. ok
 Your Qori sign-in link .. ok
 Reset your password .. ok
 Verify your email address .. ok
```

Before this, nobody had read a Qori email. `MAIL_MAILER` was `log` locally and
`array` in tests, so every message went to a log file or into a fake, and the
suite could not close the gap: seventeen send assertions, none of which renders
a template.

The suite still does not open a socket. `.env.testing` stays on `array`, and
what PHPUnit covers is every judgement the command makes, as pure functions over
a string.

## Departures

**`MagicLinkLoginController::LIFETIME_MINUTES` is public now.** The command needs
the same lifetime the real flow signs links for, and `urlFor()` was already
public. The alternative was writing `15` in a second file, which is the rule
`CLAUDE.md` states about interpolating a value rather than restating it. One
word, no behaviour change.

**A ninth test case.** The spec listed eight. I added
`test_a_resolvable_key_printed_as_text_is_also_caught`, because rewriting the
check around lang file names means both leak modes are now catchable and only
one of them was covered.

## Found, not fixed

- **Two agents were writing to this working tree at once, and the suite lied
  about it.** `cursor` claimed `T-010` partway through this task. Three separate
  times I hit failures that were not real: an undefined method mid-write, and
  then seventeen failures across `PublicSeriesTest` and `TerminologyTest` from a
  half-written migration, all of which passed when re-run a minute later. The
  board's collision check compares **file claims between tasks**, which worked —
  our Files tables are disjoint. What nothing catches is that `composer ci:check`
  is not meaningful while somebody else is mid-edit. A worker cannot tell a real
  failure from a neighbour's keystroke, and the honest fix is a worktree per
  agent rather than a rule.
- **Qori still sends no receipt**, and `Peer` and `EmailSuppression` both carry
  docblocks reasoning about "the receipt-and-access email". Named when this task
  was specified; still true; still needs its own task with a product decision in
  it.
- **The runbook's "How to run" section is stale.** It describes Atlas, Mongo and
  `TruncatesMongoCollections`, none of which exists since the move to Postgres.
  I added a mail section beside it and deliberately did not rewrite the rest,
  because that is somebody's afternoon and not a line in this task.
- **Mailpit's chaos mode is still the tool for `RecipientStatus::Failed`**, the
  enum case with no producer. Not built, and now one `docker compose` away.
