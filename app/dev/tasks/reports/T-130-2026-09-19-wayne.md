# T-130 — report

## Outcome

An Episode can now hold several materials beside its own item. Under every
Episode on the creator's Series page, a collapsed list (its summary is the
count) holds the slides, readings, worksheets and homework a creator adds —
each a file uploaded to Qori's storage or a pasted `https` link that Qori
shows and never follows. A creator labels each as preparation, material or
homework, chooses on a live Episode whether it is listed with the Episode or
after the session, gives homework a brief and a due date read in the Group's
zone, and edits or removes any of them. Removing a material, removing its
Episode, or purging its Series deletes the Qori-hosted object behind it and
the upload row with it. Materials live in their own `materials` table, count
towards no certificate, never appear on the public page, and are refused past
thirty per Episode with the number named. The Peer's side is `T-131`.

## Departures

- `MaterialList` re-mounts the add form after each successful add (above), and
  `MaterialForm` drops the asset id when the uploader's "Replace" empties its
  path, so a form never posts an upload the creator has thrown away.
- Every row shows its note, not only homework's brief.
- `update()` and `remove()` find the Series by a scoped lookup on
  `series_id` rather than through the `series` relation.
- Both material Form Requests carry `authorize()` returning true, as every
  other request in `app/Http/Requests/Share` does.
- `MediaAssetPurpose`'s class docblock said it held one case "today"; it now
  says how each case finds its prefix.

No file outside the Files table was touched.

## Found, not fixed

- An upload is confirmed the moment a file is chosen, before the form that
  attaches it is saved, so a file chosen and then abandoned — the page closed,
  "Replace" pressed, the save refused — stays stored under `materials/` (or
  `episodes/`, the same today) with a row nothing points at, and nothing ever
  deletes either → draft T-148
- `FileUpload.vue` still writes "Replace", "Uploading…" and "Choose file" in
  English, and the material form now shows them → T-006
- On a 375px screen the list's text column beside Edit and Remove is about
  190px wide, so a 200-character title takes ten lines; everything stays
  reachable → decided: the acceptance asks for usable, which it is, and a
  stacked row on a phone is a layout call for the next design-review pass on
  this page
- The public page and the Peer's page were not changed, and the Peer's page
  shows no materials at all until `T-131` → T-131
- `TaskBoardTest::test_a_spec_overlap_names_the_task_the_file_and_the_report`
  loops over the live board's overlaps, and once these three tasks closed no
  `ready` task shares a file with a recent report, so it asserts nothing and
  PHPUnit counts it risky → decided: it will assert again the moment a ready
  spec names a recently reported file; a fixture-backed case is a one-line
  change for the next task that edits `TaskBoardTest`, not a task of its own
