# T-030 — report

## Outcome

The Series summary is a textarea with a live character count beside it, and the
limit is one number. `config('qori.limits.text.series_summary')` is read by the
Form Request and sent to the page, so the browser's `maxlength` and the
validator's `max` cannot disagree. Before this the field was a single-line
`<input>` validated at a thousand characters, so a creator wrote a paragraph
through a forty-character window with nothing on screen saying where the end
was, and the browser happily accepted a 1,001st character for the save to
refuse afterwards.

Two components came out of it: a `Textarea` primitive beside the existing
`Input`, and a `TextareaField` composing label, textarea, count and error. There
was no `<textarea>` anywhere in the product before this.

No rich text editor, per the owner's instruction on 10 September 2026. Nothing
here renders unescaped HTML and the count is two numbers and a slash, so no lang
key was needed.

## Where the specification was wrong

| Section | Said                                                            | Actually                                                                                                                                                                         |
| ------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scope   | "the one field in the product that needs it today"              | Correct, and worth stating as a finding rather than as a scope note. There is exactly one long-form field a person can type. See below.                                          |
| Code    | `TextareaField` props including `modelValue` and `defaultValue` | Both are needed and the component has to hold its own value to serve them. Written as a passthrough it would show a count frozen at the initial length on the uncontrolled form. |

## Departures

**None to the built result.** The one implementation choice the spec did not
make is that `TextareaField` keeps an internal `ref` mirrored to
`update:modelValue`, rather than being a thin passthrough. The create form
submits through Inertia's `Form`, which reads the DOM and passes only a starting
value; `T-031`'s form binds a model. One component serves both only if it holds
the value.

## Found, not fixed

- **Three more fields are validated with no form behind them.**
  `subscription_prices.tagline` and `features.*` are in
  `StoreSubscriptionPriceRequest`, and the admin pricing form collects neither.
  `campaigns.body` has no form at all. All three are `T-012`'s shape — a rule
  with no way in — found while looking for something else. `T-014` owns them.
- **`series.title` is 255 characters in a single-line input**, which is correct
  and worth noting because the two limits now look inconsistent side by side.
  A name is not prose.
- **The count has no warning state.** It reads the same at 12 characters and at 999. A colour change near the limit would help and is a design decision
  nobody has made, so it is not here.
