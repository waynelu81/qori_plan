# T-050 — report

## Outcome

A creator can now find the link to their own public page. The Series builder
carries a "Share this link" panel holding the URL in a readable field with a
copy button beside it, above the panel that adds one person at a time. A draft
shows the same panel with no URL and one line saying the link starts working
when the Series is made ready.

Everything behind that link already worked. This is the half of the funnel that
was missing.

## Verified

Browser, dark theme, against `localhost:8001`, plus four server cases.

| What                  | How                                                                   | Result                                                                                   |
| --------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| The published state   | The Series builder for a published Series                             | URL in a mono field, Copy beside it, the sentence underneath                             |
| **The URL resolves**  | Take the prop, request it, assert the public page renders that Series | 200, `public/Series`, same title                                                         |
| The draft state       | A draft Series, read from the DOM                                     | No field, no button, "The link starts working when you make this Series ready to share." |
| An archived Series    | Server case                                                           | No URL                                                                                   |
| The copy failure path | Clicked Copy in the pane                                              | "Couldn't copy it. Select the link above and copy it yourself."                          |

**The second row is the one worth having.** Asserting the prop alone proves a
string was built. Asking the router the second question is what would catch a
URL that names a route correctly and resolves to nothing, which is the failure
that makes a shared link worse than no link.

**Could not verify: a successful copy.** The browser pane denies the
`clipboard-write` permission outright — `navigator.permissions.query` reports
`denied` on a secure context with the document focused — so `writeText` throws
every time here. A real browser grants it for a user gesture on a secure origin.

That turned into the useful half of the finding: the branch that is hard to
reach on purpose is the one this environment reaches every time, and it reads
correctly. The happy path is unproven in a browser and is one `await` and a
state change.

## Where the specification was wrong

| Section | Said                                         | Actually                                                                                             |
| ------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Code    | `'publicUrl' => …` as a single prop          | Three values travel together: the URL, the sentence, and the copied confirmation                     |
| Copy    | Three lang keys, unstated how they reach Vue | Two of the three name the Series noun, so they have to be resolved server-side through `Terminology` |

The spec asked for a bare `publicUrl` and separately for three lang keys, and
did not join them. Both sentences interpolate the Series noun, which is
configurable per Group, so neither can be written into the component — they have
to arrive as props already resolved. A `share` object holding all three is one
prop rather than four, and keeps the URL and the sentence about the URL from
disagreeing about whether there is one.

## Departures

- **`share: { url, note, copied }`** instead of `publicUrl`. Above.
- **The panel sits above "Give someone access", not below it.** Handing out a
  link is what a creator does with a Series they have just made ready; adding one
  person at a time is the narrower case, and that panel can currently only reach
  somebody who already has an account (`T-043`).
- **The field is `readonly`, not `disabled`.** A disabled input cannot be
  focused, so its text cannot be selected with a keyboard, which takes the link
  away from exactly the person least able to use the button. It also selects its
  whole contents on focus.
- **`aria-live="polite"` on the sentence.** The only thing that changes on a
  successful copy is one line and an icon, and without it the button appears to
  do nothing to anybody not watching it.

## Found, not fixed

- **Nothing sets a price.** No form has ever sent `price_cents`, and the update
  request's docblock says so and says why. So the link a creator can now share
  leads to a page that will say "Free" for every Series anybody has made through
  the interface. The link is still worth having and the pricing gap is the next
  thing in this stream.
- **No open-graph tags on the public page.** A link built to be posted on social
  media will unfurl as a bare URL with no title, no summary and no image. Out of
  scope here and named in the Scope as its own task, and it has a real question
  in it: there is no cover image for a Series, only generated initials.
- **The panel shows for an archived Series** with the draft sentence, which says
  the link starts working when it is made ready. Technically true, since
  unarchiving returns it to draft. It reads oddly beside the archive panel
  directly below saying it is archived.
