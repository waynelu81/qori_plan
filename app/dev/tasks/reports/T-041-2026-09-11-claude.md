# T-041 — report

## Outcome

The documentation names Neon Postgres. About a hundred references to MongoDB and
Atlas are resolved: the ones describing how Qori works are corrected, the ones
recording a decision that was made and reversed are kept and marked, and the
archive is untouched.

Three of them mattered more than the rest. `docs/project-plan.md` §20 opened
"**Database:** MongoDB Atlas … **no SQL anywhere in the app**", and `CLAUDE.md`
sends every agent to that file for architecture. Every recipe in `docs/tinker/`
opened `DB::connection('mongodb')`, so they did not mislead, they simply failed.
And the runbook's "How to run" described an Atlas cluster and a truncation
harness, which is what `T-020` would have rehearsed a restore against.

`DocumentationTest` holds the line with two checks: no live document names Mongo
or Atlas outside a reasoned allow-list, and **no document anywhere but the
archive carries a runnable artefact** — a connection string, a config value, a
package name, a cluster tier. Prose may explain what changed. Instructions may
not be for a database that is gone.

**Could not verify:** whether every rewritten _explanation_ is right, as opposed
to merely free of the word. I re-argued each "MongoDB has no foreign keys"
passage rather than substituting, and I believe the conclusions survive — a
foreign key constrains which group a row may belong to, never which group a
query reads, which is why `BelongsToGroup` is still the only guard. But that is
reasoning, not a test, and a reader who disagrees should say so.

## Where the specification was wrong

**Nothing, and the spec's own instruction is what found the bug.** It said each
"MongoDB has no foreign keys" argument must be re-argued rather than
find-and-replaced, and that a premise can go stale while its conclusion
survives. Following that literally into `docs/tinker/series.md` meant running
the rewritten query instead of writing it, which is how the finding below
surfaced.

## Departures

**Two sentences fixed beyond the Mongo sweep.** In `docs/flows/series.md` and
`docs/project-plan.md` §21.4 the Mongo claim and the embedding claim were the
same sentence. Correcting half of a false sentence is not an option.

**`QORI-004` rewritten rather than struck through.** Its original form — "local
Mongo is standalone while transaction-dependent design assumes a replica set" —
looked resolved by the move to Postgres. The topology half was. The assumption
half is live and now has evidence, so the entry names it.

**A fourth test case.** The spec listed three. The artefact check is the fourth
and it is the one that will actually catch a regression, because the word check
has an allow-list and the artefact check very nearly does not.

## Found, not fixed

- **Episodes are not embedded, and two comments say the absence of a transaction
  is fine because they are.** `episodes` is its own table with a foreign key and
  thirty-eight rows; `Series::episodes()` is a plain `hasMany`. There is no
  `DB::transaction` in `SeriesService`, and `removeEpisode()` performs one delete
  and N updates under a comment reading "one document write with no half-applied
  state". A failure partway leaves the hole the comment says it prevents.
  **`T-042` written.** This is the most valuable thing in this task and it came
  out of running a documentation example rather than reading it.
- **`inet_server_port()` answers 5432, not 5433.** That is the port inside the
  container; the host maps 5433 to it. My first draft of the recipe told the
  reader to check the wrong number. It reads config now.
- **`docs/project-plan.md` still uses the retired vocabulary** — workspace,
  course, lesson — in the sections I did not rewrite. `CLAUDE.md` already warns
  that the code is the authority. It is a real job and not this one.
- **`PLAN.md`'s stream table lists seven streams and omits `onboarding`**, which
  has a stream file and six tasks. One line, and that file is at 148 of its
  150-line cap.
- **`docs/planning/operations-and-observability.md` describes retention by TTL
  index, which Postgres does not have.** Marked superseded with a pointer to the
  scheduled-command shape `T-010` uses, but nobody has decided how activity-log
  pruning actually happens now.
