# T-054 — report

## Outcome

A creator can now price a Series from its details form, in one of nine listed
currencies, and empty the field to make it free again. Price and currency are
one pair: the request refuses a price without a currency, the service writes
both or neither, and a database check constraint refuses a row with one and not
the other — including an empty-string currency, which is no currency. A creator
types major units; the service stores cents, in the one place that multiplies.

Repricing changes what the next person pays and nothing about anyone who
already has access, because an access row carries its own price and currency
from the moment it was granted. That was the question that kept the price off
every form, and the data had answered it all along; both docblocks that called
it open now say so.

When a price is set in a Group with no payout account, the form says "Nobody
can pay for this Series until you connect payouts" with a link to Payouts — the
creator hears it before a buyer is refused at checkout.

## Where the specification was wrong

| Section  | Said                                                                                  | Actually                                                                                                                                                                                                          |
| -------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Code     | `'currency' => ['sometimes', 'nullable', 'required_with:price', …]`                   | `sometimes` skips every rule when the field is absent, and absent-with-a-price is exactly the case `required_with` exists to refuse. Case 3 caught it. The rule has no `sometimes`.                               |
| Code     | `route('share.payouts.show', $group->slug)` in the controller, with `$group` the slug | By the time the controller runs, the route binding has resolved that parameter to the model; coerced to string it is the model's JSON, and the URL generator choked on it. The resolved `$scope` is used instead. |
| Database | `CHECK ((price_cents IS NULL) = (currency IS NULL))`                                  | Treats `''` as a currency. The constraint reads `(currency IS NULL OR currency = '')` on the right, which is the same rule with the hole closed. Recorded as a departure below too.                               |

## Departures

**The constraint also refuses an empty-string currency.** The spec's expression
would have let `''` through, and `''` is the exact value `Connect::checkoutFor()`
would send Stripe. One extra arm, same rule.

**`SeriesService::update()` reads `$attributes['currency'] ?? ''`.** The
analyser is right that the key may be absent from the declared shape; the
request guarantees it is present whenever a price is, and if that guarantee
ever fails the constraint refuses the row rather than storing a blank.

**The currency `<select>` is native**, styled like `TimezoneField`'s, rather
than the shadcn Select. Nine short codes do not need a searchable listbox.

## Found, not fixed

**The `$group` parameter on `SeriesController::show()` is not the slug its
comment says it is.** Its comment reads "that is a slug, and it is only in the
signature because route parameters arrive positionally"; at runtime it is the
Group model coerced to JSON, which only works because nothing was reading it.
Every controller method with a `string $group` parameter under `/g/{group}`
deserves the same look. Needs a task.

**Three `?? 'USD'` fallbacks** in `public/Series.vue`, `share/series/Index.vue`
and `admin/Creator.vue` are now dead for a priced Series. They go with the
shared money formatter, which is its own task.
