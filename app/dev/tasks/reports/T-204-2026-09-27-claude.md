# T-204 — report

## Outcome

Laravel Cloud's scheduler has been seen on Qori's own environment, and it
does what its guide says. A throwaway command ran every ten minutes for four
hours and twenty minutes on 26 September 2026. All 27 runs happened, none
twice, each 5 to 52 seconds after its minute, and 18 of them found the
environment asleep and woken for that run. So a schedule can send the
recording email reliably, under a minute late. What it costs is the wake:
each run keeps the environment up for the sleep timeout, which the runs put
under ten minutes. The probe is gone from the code and from production.
Choosing the interval moved to `T-206`, with the two questions only the
owner's dashboards can answer.

**Could not verify:**

- **The sleep timeout's value.** The runs put it under ten minutes; it is a
  setting on the App cluster, which only the owner can read (`T-206`).
- **Whether Neon's compute or the cache slept between runs.** The probe kept
  its runs in the cache and never queried the database, by design, and the
  dashboards are the owner's (`T-206`).
- **What woke the environment the five times neither the probe nor a read
  did.** No request log was read. The times were irregular, which suggests
  visitors or crawlers rather than a monitor.
