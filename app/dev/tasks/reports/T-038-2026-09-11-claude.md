# T-038 — report

## Outcome

Every auth screen and every error page now shows the mark with the Qori wordmark
beside it. One component, `AppLogoLockup`, renders the pair, and the sidebar and
the auth header compose it differently. The error layout gets the wordmark as
markup, so it still renders with no build and no application.

## Verified

Browser, dark theme, against `localhost:8001`:

| Screen             | Before             | After                                     |
| ------------------ | ------------------ | ----------------------------------------- |
| `/auth/login`      | Gold tile, no name | Tile with **Qori** centred underneath     |
| A 404 page         | Gold tile, no name | Tile with **Qori** beside it, on one line |
| Sidebar, open      | Tile and name      | Unchanged                                 |
| Sidebar, collapsed | Tile only          | Tile only. The wordmark does not leak     |

The collapsed sidebar was the one worth checking. `AppLogo` used to emit two
sibling elements straight into the menu button's flex row, and it now emits one
wrapper around them, so icon mode could have started showing a sliver of text.
It does not.

`LockupTest` also asserts the error layout contains no `@vite` and no `/build/`,
because the wordmark being a component import rather than markup is the exact
regression that would make a 500 page depend on a successful build.

## Where the specification was wrong

| Section | Said                               | Actually                                                                                                              |
| ------- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Code    | `orientation?: 'row' \| 'stacked'` | Orientation is not the only difference. Row is `size-8` on `bg-sidebar-primary`; stacked is `size-10` on `bg-primary` |

The sidebar has its own palette, so the two placements differ in tile size, mark
size and colour token as well as direction. The prop carries all of it rather
than growing into four props, and the component says so in its docblock. The
alternative — a genuinely orientation-only component plus per-caller classes —
puts the identity back in the callers, which is what this task existed to stop.

## Departures

- **`AppLogo` is now three lines.** It became a composition of the lockup rather
  than a copy of it. Its name is kept because `AppSidebar` imports it and the
  sidebar's composition is a real thing to name.
- **The error layout's wordmark reads `config('app.name', 'Qori')`**, matching
  the `<title>` immediately above it, rather than a literal.

## Found, not fixed

- **`Welcome.vue` still places `AppLogoIcon` directly.** The public page was
  explicitly out of scope and `R-002` says so, but it is now the only surface
  composing the mark by hand. Whoever does the public header should take the
  lockup.
- **Copy defect on the receiving home**, seen while signed in for this check:
  "Set up your own school and publish series to the people you already know."
  Qori is not a school, and `series` is lowercase where the product noun rules
  require the stored form. Nothing to do with this task; it belongs with `T-011`
  or `T-006`.
