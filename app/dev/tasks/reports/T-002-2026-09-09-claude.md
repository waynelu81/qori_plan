# T-002 — report

## Outcome

The 404 was Laravel's bare white view, reached by the people least able to
tolerate it — somebody following a stale Series link, a Peer whose access was
revoked. Six statuses now render in the paper/gold palette on a shared frame,
in both themes, each offering a way onward.

The larger result was not in the spec. `AppException::render()` called
`abort()` for a failed GET, and Laravel's own 404 view is three lines that
hardcode `__('Not Found')` — so every §23 message ever written for a page load
was being discarded. A dead Series link said "Not Found" while "That series is
no longer available" sat unused in lang. It says the right thing now.

## Where the specification was wrong

| Section     | Said                                                                                                 | Actually                                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Scope → Out | "Anything `AppException` renders — it already produces its own page with a message and a resolution" | False. `render()` calls `abort()`, and the framework view ignores the message. Re-scoped; the log is in the task. |
| Copy        | Six lang entries                                                                                     | Each page also needs words for its link. Two more keys.                                                           |

## Departures

Three tests beyond the seven specified, all from the re-scope: an
`AppException`'s message, its resolution, and a status with no Blade file
falling back rather than becoming a 500.

The layout was redesigned mid-build. The first version used
`$resolution ??= __(...)`, which had two faults: `__()` returns the _key_ when
a line is missing, so the 500 page rendered the literal string
`errors.pages.500.resolution`; and an unset variable is indistinguishable from
one explicitly set to null, so an `AppException` that deliberately withheld a
resolution would have had the generic line put back underneath it — the exact
§23 violation the task was meant to honour. The layout is a pure renderer now
and `500.blade.php` says `'resolution' => null` where a reader can see it.

## Found, not fixed

`AppException::resolution()` falls back to the ErrorCode's generic resolution
when a specific lang key omits one. So `errors.access.series_unavailable`,
commented "Final: there is nothing to retry", tells the reader "Check the link,
or go back and try again". The omission §23 calls deliberate is undone one
level up. Not fixed here: `resolution()` also feeds the JSON payload and every
toast. Added to **T-011**.
