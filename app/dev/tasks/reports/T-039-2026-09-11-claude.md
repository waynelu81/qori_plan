# T-039 — report

## Outcome

At narrow widths a Series keeps its identifying words. On the Series page the
action drops to its own line and the title and summary take the content width;
in the list the status moves below the title and the title is allowed two lines
instead of one truncated one. Desktop is untouched.

## Verified

Browser at 375px, dark theme, then again with emulation cleared. **The visual
result was verified by eye. There is no JavaScript test runner here and layout
is not server-testable**, so nothing in the suite can see any of it.

| Screen                               | Before (`R-002`, 390px)                   | After, 375px                                       |
| ------------------------------------ | ----------------------------------------- | -------------------------------------------------- |
| Series page, longest fixture title   | **Eleven lines**, summary squeezed beside | **Six lines**, summary across the content width    |
| Series page, the action              | Beside the title, competing with it       | Own line below, full width                         |
| List row, "What Nobody Tells You…"   | Truncated to "What Nobody Tells Y…"       | Reads in full over two lines                       |
| List row, "Notes From Twelve Years…" | Truncated                                 | Reads in full                                      |
| List row, the 71-character fixture   | Truncated                                 | Still clamps, at two lines — bounded, as specified |

Desktop, emulation cleared: list rows are one line with the status at the right,
and the Series page has cover, title and action on one row. Unchanged.

Other `PageHeader` callers checked at 375px, since it is shared and a header fix
that helps Series and breaks Peers is not a fix: the Peers page and the settings
pages both render correctly.

The one thing the suite does hold is
`test_a_long_title_reaches_the_page_untruncated`: the controller sends the whole
title and every shortening is the browser's, reversible by CSS. If that ever
fails, somebody has moved truncation to the server where it cannot be undone.

## Where the specification was wrong

| Section | Said                                           | Actually                                                                      |
| ------- | ---------------------------------------------- | ----------------------------------------------------------------------------- |
| Code    | "the header's title block stops sharing a row" | The header **already claimed to do this** and its markup could not. See below |
| Files   | `PageHeader.vue`, list row, one test           | Correct, and complete                                                         |

**`PageHeader`'s docblock already said the action wraps below the title rather
than shrinking it.** It never did. `flex-wrap` only breaks a line when a child's
minimum width forces it, and `min-w-0` on the title block is a declaration that
its minimum is nothing — so the title squeezed to eleven lines and the action
never moved. The intent was right, written down, and contradicted two lines
lower by a utility class. What makes it true now is `basis-full` on the action
below the `sm` breakpoint.

## Departures

- **A wrapper around the `before` slot and the title.** The spec said "the
  header's title block stops sharing a row with its action"; done naively that
  also stacks the cover above the title, which the spec's own decisions forbid.
  The cover and title now sit in an inner row that never breaks, and only the
  action wraps.
- **`line-clamp-2 sm:truncate` rather than removing truncation.** Two lines
  narrow, one wide. The Scope asked for a bounded row height and the titles that
  need the most words are exactly the ones a single line cannot hold.
- **`gap-4 sm:gap-6` between cover and title.** The desktop value is unchanged;
  narrow widths get 1rem back, which is a third of a word at that size.

## Found, not fixed

- **Only 375px was checked.** The Scope says this fixes what was photographed
  and does not claim the responsive lane. 360px, 768px and the zoom levels are
  unverified, and `T-022` is still blocked on a browser that renders reliably.
- **The Series page's action slot is now full width at narrow widths**, so a
  page with two actions would stack them across the whole row. Only one page has
  two today and it was not looked at under 640px.
