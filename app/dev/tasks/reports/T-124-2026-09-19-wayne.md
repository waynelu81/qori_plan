# T-124 — report

## Outcome

A live Episode can now be corrected where it is instead of deleted and
re-added. Each live row on the creator's Series page has "Edit link, time and
length", which opens an inline form holding the current join link, the start
in the Group's zone, the length and a Recorded / Live only choice. It posts
to the PATCH every Episode already had, so the Episode keeps its id and every
Peer's progress still names it. The start is read in the Group's zone exactly
as on create — both requests share `App\Concerns\ReadsGroupLocalTime` — and
may be in the past, so a class already held can take its real time. Every
write to a live Episode's `content` now goes through
`LiveSessionService::withLockedContent()` under a row lock, and a save that
moves the start or the end bumps `content.schedule_version` once, which
`T-133`'s calendar file will read. The toast names the new start with its
zone when the time moved and says "updated" otherwise; nothing is emailed,
and the form says so.

## Departures

- The edit form closes after a successful save (`@success`), so the row's own
  line is what says the new time. The spec named the Close button and not what
  a save does to the form.
- The Recorded radios check "Recorded" whenever `records` is not `false` and
  "Live only" when it is, rather than `:checked="episode.records"` and its
  negation; the same on every live row, where `records` is never null, and
  safe on a row where it is.
- The comment above the create form's switch in `LiveSessionPanel.vue`, which
  `T-123` wrote to say the edit form used the same pair, now says the edit form
  asks with two radios.

No file outside the Files table was touched.
