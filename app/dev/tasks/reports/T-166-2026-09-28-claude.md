# T-166 — report

## Outcome

Stripe's `account.updated` now moves a Group's payments readiness by itself.
The Connect endpoint hands the event's account id to
`PaymentsService::refresh()`, which reads the account again, once, and keeps
what the read found on every Group holding the id, as a visit to Integrations
does. So a creator who finishes Stripe's steps sees the dashboard and the price
field move without opening Integrations, and an account Stripe restricts later
is noticed when Stripe says so. Only the id is taken from the event, because
Stripe does not deliver events in order. An id no Group holds costs no call,
and a read that fails gets no 2xx, so Stripe sends the event again. The live
Connect endpoint's events gain `account.updated` in `release-prerequisites.md`.
