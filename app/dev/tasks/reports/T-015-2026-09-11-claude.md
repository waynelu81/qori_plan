# T-015 — report

## Outcome

Qori can send transactional email from its own domain. `useqori.com` is
registered, on Cloudflare, resolving, and serving the application over HTTPS.
Postmark has the domain verified against a `qori_production` server, with a
custom return path and a DMARC policy. Sentry is deployed and, importantly, was
removed again from the local `.env`.

The task is the owner's work; this report records what was verified and by whom,
because "configured" is a claim and the point of this file is to say which parts
of it were checked.

## Verified

Every row was checked from this machine, by public DNS lookup or one HTTP
request. None of it is taken on report.

**Could not verify, and each matters:**

- **DKIM.** Postmark generates the selector per domain, so it cannot be looked
  up without knowing it. Postmark's own verified status is the evidence.
- **Which server token Laravel Cloud holds.** `qori_testing` and
  `qori_production` are different tokens. If the sandbox one were deployed,
  mail would be accepted, appear in Postmark's Activity, and never be
  delivered — the quietest failure available here. The owner states it is the
  production one; nothing here can see it.
- **Whether `dmarc@useqori.com` routes.** See Notes on the task.
- **Whether `APP_URL` is right.** See Notes on the task.
- **That mail arrives.** Not attempted. That is `T-032`, and it is the whole
  distinction this task ends on.

`composer ci:check` was not run, because nothing in the repository changed
except this task file and this report.

## Departures

**The task had no `Files`, `Database`, `Code`, `Copy`, `Routes`, `Tests` or
`Acceptance` section**, because it was written as a blocked stub and the board
only requires those of a `ready` task. They were added to close it, all of them
reading None, which is itself the finding: this was entirely account and DNS
work, and the repository was ready for it weeks ago.

**One acceptance box is deliberately left unticked**, naming `T-032`.
Configuration being right and mail arriving are two different facts, and a task
that ticks the second on the strength of the first is how a delivery stream gets
declared finished without anybody having received an email.

## Found, not fixed

- **The `rua` address may not route.** Aggregate reports are the entire reason
  to publish `p=none`, and the domain uses Cloudflare Email Routing, which needs
  a rule per address. If `dmarc@useqori.com` is not one, the reports bounce.
- **`APP_URL` was not among the variables confirmed.** Signed links depend on it
  exactly and fail silently when it is wrong.
- **`QORI_MAIL_BROADCAST` should still be `log`.** Broadcast is SES on
  `mail.useqori.com` and is not configured. The config default is `log`, so an
  unset variable is correct — worth stating because it is the one mail setting
  that should _not_ have changed.
