# T-199 — report

## Outcome

A person who never chose a password now proves who they are with a code
emailed to their address, wherever a password would be asked for. The confirm
step in front of the security page offers "Email me a code" beside the password
field and the passkey, and a right code confirms the session exactly as the
password does — so the security page, two-factor and passkeys open to them.
There they choose a first password without a current one, and the delete
dialog takes an emailed code in place of the password. `users.password_set_at`
says who chose one: registration, a reset and a change set it, and it is empty
for every account that existed before, since the two kinds cannot be told
apart after the fact. Nothing changes for a person who chose a password.

## Found, not fixed

- Every account the dev database and production held before this reads as
  having chosen no password, so their owners are offered the emailed code and
  asked for no current password until they set one again. That is the
  decision, since nothing tells the two kinds apart; it is written here so the
  owner is not surprised by it → decided: pre-release accounts are few and the
  owner's, and the code is as strong a proof as the reset link they already
  have
- A magic link or a code signs a person in without asking for the second
  factor they turned on; whether it should is its own question → decided: out
  of this task's scope by its Decisions, and not drafted until someone turns
  two-factor on without a password and says it surprised them
