# T-080 — report

## Outcome

The planning documents can now be edited by several people on one afternoon
without meeting in prose. A stream file states its owner, its goal and its
tasks in order, and never a status — the board says what is done, and a test
refuses a stream that says it too. `blocks:` is derived from every task's
`depends:` and the front-matter field has to agree, which found it wrong in
fourteen places. The Files-table parser reads every backticked path in a row,
expands a glob against the repository, and refuses a bare basename, so the
collision check now sees the rows most likely to collide. A "Found, not fixed"
bullet ends in a disposition from reports dated 15 September; the 123 older
ones are counted, not rewritten, and three that were repeated across reports
are now drafts `T-084`, `T-085` and `T-086`. Ids come from
`php artisan qori:tasks --new <stream> <slug>`. Decisions carry `D-###` ids and
append at the end under the day's heading, with an owner's "Decisions needed"
list read from every draft. Every rule lives once, in `TaskBoard`, and both
`qori:tasks --check` and `TaskBoardTest` apply it, so the prose in
`PROCESS.md` and the gate cannot drift apart again.

- Every report is inside the seven-day overlap window because the project is
  six days old, so "Spec overlaps" lists forty lines today. The window is a
  constant (`TaskBoard::OVERLAP_DAYS`) and the output is grouped per task; it
  becomes useful the week after next → decided: the rule is right and the
  noise is the calendar's
- `T-014` is a draft that says it should never become ready; the draft rule is
  satisfied and the stream lists it as an index. A status for "index, closes
  when its children do" does not exist → decided: not worth a status; the
  stream owner deletes it when `T-044`, `T-045` and `T-046` are done
- Fourteen older reports write "Found, not fixed" as paragraphs, not bullets,
  so the reader counts paragraphs there. A report from the cutoff that does
  the same must still end each paragraph with a tag → decided: the template
  now shows a bullet, and the reader accepts both
- `PLAN.md` says "Ten, ordered by what blocks release" and lists ten; it does
  not state the ready target the spec attributes to it. The owner's file, one
  line, when the owner next edits it → decided: the config key and PROCESS.md
  carry it until then
