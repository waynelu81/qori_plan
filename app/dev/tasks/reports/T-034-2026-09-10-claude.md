# T-034 — report

## Outcome

The Payments page no longer sends an invited admin to a page that refuses them.
The billing link is shown to owners; everybody else gets the same question
answered without one, in the words `errors.billing.owner_only` already uses.

The hole was the ordinary kind. §15 has kept billing with the owner since it was
written, `BillingController` refuses everybody else, and `AppSidebar` hides the
nav item. The Payments footer was added later and did not inherit the condition,
because the second place to mention a capability does not know the first place
had a rule attached.

## Departures

**None.** The link is gated on `auth.currentGroup.isOwner` through
`useShareContext()`, exactly as specified, with no controller change.

## Found, not fixed

- **Nothing audits the product for this shape.** The fix is one `v-if`; the
  finding is that a link to a permission-gated page can be added anywhere and
  nothing notices. `qori:reachability` looks for routes and services with no way
  in, which is the opposite question: this is a way in that should not exist for
  this viewer. A check that walked every internal `Link` and compared it against
  the guard on its destination would have found this and would find the next
  one. That is a real task and a larger one than this.
- **Six `R-002` findings remain unrouted:** F-3 through F-8. F-6 is partly stale
  after `T-031` and should be rechecked against a fresh capture first.
