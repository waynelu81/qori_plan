# T-187 — report

## Outcome

A "you're in" email the mail provider refuses no longer takes the access with
it. `AccessService::announce()` catches the send and reports it, so a Peer who
typed their code lands on the Series they now have instead of an error page
for something that worked, and a paid checkout's webhook is answered rather
than left for Stripe to redeliver into an access that already exists — with
the fulfilment recorded and the invitation marked on the first attempt, which
today's 500 postpones. Nothing is resent and nobody is told: there is no
worker, and where a creator sees a message that did not go is `T-129`'s
question, now also `T-189`'s. The catch is around the one send, so a peer
limit, a locked Series or a database that went away still reaches the caller
exactly as before.
