## Preserved architecture-review findings

The following section is retained from the former plan. It is historical evidence, not automatically current status; triage each item before acting on it.

- ~~**`compose.yaml` cannot start as written**: port 27017 is already bound by another project's `platform-mongo-1` container, and that is what local dev and the test suite have actually been talking to. It is a **standalone `mongo:7`, not a replica set**, so `DB::transaction()` will fail there even though §21.4 assumes a replica set is available.~~ **Resolved 2026-09-08.** The move to Postgres took the port with it: `compose.yaml` binds **5433** deliberately, and the comment at the top of that file records why. The replica-set concern is gone; the transaction concern it raised is not — see QORI-004.
- **CI builds depend on `fonts.bunny.net` being reachable.** `vite.config.ts` uses the starter kit's `bunny('Instrument Sans')` plugin, which downloads and self-hosts the font **at build time** with a 10s timeout — so `npm run build` inside `composer setup` fails the whole run when that host is slow. Seen once on 2026-09-06; a re-run passed, so it is intermittent rather than broken. Three ways out: vendor the font files into the repo, load it at runtime with a `<link>` in the blade layout instead of at build time, or accept the flake and re-run. Left alone because it is a front-end/design call.
- The studio frontend needs Wayfinder route regeneration (`npm run build`) before `studio.*` route helpers exist in `resources/js/routes`.
- Mail still needs a Postmark account: the transport is installed and the config reads `POSTMARK_API_KEY`, but nothing is set, so `MAIL_MAILER=log` remains everywhere and verification / reset / magic-link / access mail goes to the log. Needs an account, a verified sender signature on the Qori domain, and `MAIL_MAILER=postmark` + the key in the Laravel Cloud dashboard.
- `MAIL_FROM_ADDRESS` is still `hello@example.com`.
- **A student can be charged and refused access.** `CheckoutService::fulfil()` reaches `guardContactLimit()` through `contactFor()`, so a workspace at its contact cap throws _after_ Stripe has taken the money — uncaught, so Stripe retries for days and fails every time. Live on the free plan today at 50 contacts, not only after a downgrade. Fix is to check the cap in `begin()` instead, before anyone pays.
- **Queue is `sync` everywhere, by decision** (2026-09-05) — jobs run inline and nothing is marked `ShouldQueue`. EDM will force the question. Laravel Cloud's three options, researched: **managed queue** (SQS-backed, autoscaling, failed-jobs dashboard with retry; Flex scales to zero and wakes in <1s with a 90s per-job cap; Starter allows 1 queue / 3 workers; ~$0.13/mo idle plus $1 per 1M operations) — but deploying one sets `QUEUE_CONNECTION=cloud` for the environment, **silently overriding** whatever is set, and needs `aws/aws-sdk-php`, which is not installed; **worker cluster**, which keeps any driver; or an **app-cluster background process**, which is free but gets stopped mid-job when a scale-to-zero environment sleeps — so it is the wrong choice here despite being the cheapest.
- Local mail is MailHog on `:1025` (inbox at `http://localhost:8025`); `.env` ships as `log` so no container is required. Laravel Cloud will use Mailtrap for testing until launch, then Postmark.
- `HandleInertiaRequests` shares the whole `User` model — future fields auto-leak to the frontend. The staff prop added alongside it shares only name and role, so the fix is to make `user` match that shape; the blocker is auditing which fields the Vue pages actually read.
- `User.php` docblock still claims other tables live on sqlite.
- i18n (§13) unwired — cheaper now than after 40 Vue pages.
